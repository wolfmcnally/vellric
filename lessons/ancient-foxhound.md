As of 2026-10-21, a configured read-only critic was launched with the declared tools Read, Grep, Glob and WebFetch, and the caller explicitly prohibited shell execution. Its actual trace nevertheless recorded one Bash inventory command accepted by inherited configuration. The command counted and searched an already allowed source patch and listed filenames in its review directory; no protected transcript bytes, credentials or product execution were observed. The declared allow list therefore did not establish the promised execution exclusion in that launch.

Check the actual supported tool-denial or tool-availability surface, inherited permission semantics and observed tool trace before claiming a reviewer cannot execute commands. If the wrapper cannot express the intended restriction, report the gap rather than silently changing identities, settings or grants. A violated review remains nonqualifying; preserve it, reconstruct actual data flow, and rerun the affected review within its existing budget. Clean source that predates the violation does not need rewriting merely because the reviewer crossed a tool boundary.

The 2026-10-21 correction preserved the first failed review, checked its exact command/results, and used the remaining permitted fresh review pass with a source-only Read/Grep/Glob contract. No engine, global permission or provider setting was changed in that correction. Any executable enforcement change and its real denial fixture require the operator's separate ratification; this candidate lesson is not a graduated rule.

As of 2026-10-29 UTC, the operator explicitly authorized one additional bounded plan pass with enforced tool restrictions, preserving the nonqualifying pass and cumulative count. The narrowly authorized correction adds a fixed source-review invocation profile to the canonical manager rather than constructing another launcher. Qualify the actual supported built-in inventory flag and MCP denial separately: an approval list is not an inventory limit, and limiting built-ins alone does not remove MCP tools. Use the project's explicit formatter configuration when formatting root tools; running its Python wrapper from a different directory does not by itself select the project's formatting rules. This entry records the correction and diagnostic learning, not graduation of this candidate lesson.
