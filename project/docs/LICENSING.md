# Licensing and source

As of 2026-10-21, version 0.2.3 uses public Conric 0.1.0 (MIT) and PyYAML (MIT) in the runtime closure. Conric's separately installed wheel carries its MIT license; its public source is pinned exactly in the manifest and lock. The installed dependency inventory below records the current OCR and vision closures on macOS arm64, with actual notice hashes and locked source identities; it does not qualify Windows bundle distribution or native source/build closure. Vellric's existing grant and notices are unchanged. The source integration is public; tagged release artifacts require release qualification, and Windows bundle distribution remains separately restricted.

Vellric 0.2.3 is AGPL-3.0-only. [Full GNU text](../LICENSE), [NOTICE](../NOTICE) and the original Drawbridge/Starter MIT grants under LICENSES accompany the wheel/source. Those retained grants remain operative; no commercial Artifex grant is claimed.

The project wheel ships Vellric source, docs and notices. PyMuPDF/MuPDF and optional OCR dependencies/system engines install separately and keep their own AGPL/MPL/LGPL/Apache/BSD/MIT and component notices. The exact installed dependency inventory is [dependencies-qualified.json](dependencies-qualified.json); actual notice texts are retained in the local release companion, while the lock records registry source archive hashes and Conric's immutable source commit. This is not a wholly permissive OCR stack. The optional `vision` extra installs MIT-licensed `anthropic` 1.12.0 and its locked dependencies, now included in that inventory. Human real-provider acceptance remains separate.

Historical v0.2.2 ruling: as of 2026-10-21, the operator approved v0.2.2’s `vellric-0.2.2-py3-none-any.whl` and `vellric-0.2.2.tar.gz` for qualified Conric, native and OCR use, conditional on every other mandatory release gate passing. **Cloud-vision human acceptance remains OPEN and UNQUALIFIED.** This one-release exception does not close the real-provider tests, authorize provider calls or credentials, qualify cloud-vision output, or permit Windows binary distribution.

The prepared release publishes matching project wheel/source/lock/build material. Its concrete sequence is in [release preparation](RELEASE-PREPARATION.md). A future environment/container that redistributes third-party binaries needs corresponding materials for those actual binaries; that is a separate artifact, not a theoretical hold on these project packages.

The Windows bundle built by `packaging/windows_bundle.py` is such an artifact: beside the project wheel it holds the unmodified binary wheels of PyMuPDF and the OCR extra's other dependencies, each with the license files its own wheel carries, and no assembled source or notice closure. It exists so that a user can install on their own machines where no package index is reachable, and the repository's workflow builds and installs it without publishing it. The owner ruled on 2026-10-10 that workspaces of colleagues inside the owner's own organisation count as the owner's own machines for this purpose. Giving the bundle to anyone outside it is redistribution of those binaries and needs the corresponding materials first.

Drawbridge retains MIT and invokes this independently installed complete-job CLI. It does not import Vellric or PyMuPDF. Its public PDF fixtures retain CC-BY-SA/IETF grants separately. Keep each package's source/NOTICE identities together when installing or distributing it.

Version 0.2.3 adds no packaged dependency or binary: its macOS observer calls the host-provided libproc API. The matching release notes record the exact qualified source/artifacts and measured platform/caller-profile results. Cloud-vision human acceptance remains OPEN and UNQUALIFIED; no third-party binary redistribution is implied. The historical v0.2.2 exception remains specific to that earlier release.
