# Platform and extraction qualification

The standalone CLI is qualified on macOS and Linux arm64 with English native and OCR fixtures. Use independently installed Vellric and run doctor before recognition. Other architectures/languages, production sizing and hard hostile-document containment require their own qualification.

The native fixture asserts an exact typography/word golden. Mixed fixtures recover intrinsically rotated scans and ignore stale hidden OCR. The long-scroll fixture retains all 59 visible lines in five 300-DPI bands. Preserved public PDF fixtures cover 27 pages of exact native text, OCR selection and image coverage. The two image cases preserve text; upright-column rotation metadata is corrected and confidence values differ. Representative public/synthetic originals and readable text are in [samples](samples/index.html). These unchanged text cases have no blanket human readability hold.

The qualified engine closure uses PyMuPDF 1.28.2, OCRmyPDF 17.7.0, Tesseract 5.5.2 and explicit English/OSD traineddata. macOS Ghostscript is 10.07.1; Linux Ghostscript is 10.00.0 with Leptonica 1.82.0 and qpdf 11.3.0. The [component inventory](qualification-linux-full-ocr.json) retains actual upstream package/license/source/data hashes; the [current dependency inventory](dependencies-qualified.json) complements it. Python project artifacts install these dependencies independently and do not bundle their native engines.

Run `./bin/check all` from the repository root. The package's tests include actual OCR cases and do not silently skip missing qualified engines. Release packages must be rebuilt from the exact fresh public commit, reproduce with the fixed build epoch/constraints, and pass isolated native/full-OCR installs. See [installation](INSTALLATION.md) and [release preparation](RELEASE-PREPARATION.md). Private execution traces and historical package/Git identities are excluded; previous implementation qualification does not substitute for the exact public candidate's gates.

Vellric's project grant is AGPL-3.0-only. Original Drawbridge/Starter MIT grants and copyright remain operative. Copyleft dependency components retain MPL/LGPL/AGPL terms and their own source/notices; do not relabel the closure as wholly permissive. The standalone wheel/source route distributes project code/docs/notices, with dependencies installed separately. A future bundled wheelhouse/container would require its own exact native source/license closure. No commercial Artifex grant is claimed. The watchdog can overshoot and is not a hard sandbox.

## Native consumer identity qualification

The qualified engine uses PyMuPDF/MuPDF 1.28.2. Against a prior consumer using PyMuPDF 1.28.0 with MuPDF 1.29.0, the six public/synthetic sample pages retain exact RGB hashes and difference hashes. First-page PDF derivatives differ only in engine-written header/producer metadata on these samples. This is not byte parity across engine versions: newly cut files acquire new hashes. Preserve existing derivatives and stores during a source/runtime upgrade; any later re-cut or intake run requires its own explicit operational scope. Range determinism and exact bytes against the currently qualified engine remain executable assertions.

The six synthetic image comparisons (RGBA, grayscale and CMYK, at original and downscaled dimensions) also preserve exact RGB and difference hashes against the prior consumer engine. Drawbridge and consumer runtime imports remain engine-free; development fixture environments still install PyMuPDF and retain its license terms.
